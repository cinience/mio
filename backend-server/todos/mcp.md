## MCP 代码审阅与优化任务清单（backend-server）

面向 internal/domain/mcp、internal/app/server/websocket/mcp.go、internal/app/server/chat/session_mcp_tool.go 等模块的审阅与优化建议，拆解为分阶段、可执行的任务。

---

### 发现的问题（Review 摘要）

- 启停与生命周期
  - MCP 管理器（本地/全局/设备）启动与停止流程存在耦合但未纳入应用统一 Shutdown 链；缺少 `context.Context` 贯穿，无法优雅关闭。
  - WebSocket 端点建立后仅依赖 `session.Ctx.Done()` 清理设备连接，未提供显式 `Close/Shutdown` 路径与幂等保障。

- 资源与会话管理
  - 设备级 MCP 客户端池 `Add/Remove/Get` 缺少超时/容量/老化策略，潜在泄漏风险；工具视图合并策略（本地→全局→设备）未暴露冲突解析策略与优先级可配置项。
  - `GetAudioResourceByTool` 未实现资源读取流程与错误回传，暂为占位。

- 可靠性与限流
  - WebSocket 端点鉴权可选，但缺少速率限制（连接/消息/工具调用），易受滥用影响；缺少心跳、空闲 TTL 和最大会话存活策略。
  - 与远端 MCP/工具交互缺少统一的超时、重试（指数退避+抖动）、熔断与降级策略。

- 并发安全与观测
  - 客户端池与工具表的并发访问需要确认全部走互斥/原子容器，建议补充读写压力下的测试与基准；
  - 指标与日志粒度不足：连接数、活跃设备数、工具解析耗时分布、调用成功率/错误率缺失；错误分级与抽样日志未统一。

- 结构与可维护性
  - WebSocket 层与 MCP 会话/设备池耦合紧；建议通过接口抽象与 `OnNewConnection` 事件桥接；
  - 工具合并逻辑散落在 `mcp_client.go`，不易扩展新优先级策略；缺少配置与策略对象。

---

### P0（立即执行）

- [ ] 将 MCP 管理器与设备会话纳入应用生命周期
  - 在应用启动处调用 `mcp.StartMCPManagers()`，在 `App.Shutdown(ctx)` 中调用 `mcp.StopMCPManagers()`；
  - 为设备会话池提供 `CloseAll()` 并在 Shutdown 时清理；确保幂等。

- [ ] 全链路传递 ctx 与超时
  - `MCPManager.Start/Stop`、设备会话创建/关闭、工具调用与资源读取均接收 `ctx`；
  - 远端交互设定默认超时（可配置），并在上游可覆盖。

- [ ] WebSocket 端点健壮性
  - 在 `handleMCPWebSocket` 中加入：连接速率限制、同设备并发连接上限、空闲 TTL（读/写超时）；
  - 在会话结束与错误路径显式调用 `mcp.RemoveDeviceMcpClient(deviceID)`；
  - 为 `WsEndPointMcpClient` 增加 `Close()`，封装底层 `conn.Close()` 与通道关闭，保证幂等。

- [ ] 指标与日志（基础）
  - 指标：活跃设备数、连接建立/关闭计数、工具合并来源分布、本地/全局/设备工具数量、工具调用成功率/时延直方图；
  - 日志：设备维度 `deviceID`、会话 `sessionID`，错误分级（warn/error），高频错误抽样。

---

### P1（近期）

- [ ] 设备 MCP 客户端池治理
  - 引入容量上限、LRU/TTL 逐出策略；空闲清理协程（定期扫描）；
  - `GetAllToolsByDeviceId` 错误标准化（区分未连接 vs 真正错误），调用方据此调整日志级别与指标；
  - 提供设备会话状态查询（连接时长、最近活跃、工具数）。

- [ ] 工具合并策略模块化
  - 抽象 `ToolMergeStrategy` 接口，默认策略：本地 > 全局 > 设备；
  - 支持策略配置（按名称优先/按标签优先/允许覆盖/禁止覆盖），并输出冲突计数指标；
  - 对外暴露合并快照与来源说明，便于调试。

- [ ] 可靠性策略
  - 工具调用与资源读取：统一超时、指数退避重试（maxAttempts、jitter）、熔断（错误率/平均时延窗口），
  - 降级：设备工具不可用时回退至本地/全局工具；资源读取失败返回合理的错误码与提示。

- [ ] WebSocket 端点安全与限流
  - 端点级 QPS/并发限制（全局与设备级）；消息大小限制；
  - 心跳/健康探测（ping/pong），异常断开检测与快速回收；
  - 鉴权结果缓存（短 TTL）与失败惩罚（延迟/封禁窗口）。

---

### P2（中期）

- [ ] 观测完善
  - Prometheus 指标面板：连接/设备趋势、工具分布、耗时/错误率；
  - Trace：工具调用链路（WS/MCP → 工具解析 → 远端调用/资源读取）。

- [ ] 配置与策略中心化
  - `mcp.config` 结构：超时/重试/熔断、限流、池容量/TTL、合并策略、日志级别等；
  - 支持热更新（对无损参数），并下发到活跃会话。

- [ ] 测试与基准
  - 单测：设备池并发、安全限流、策略覆盖；
  - 端到端：多设备并发接入、工具合并冲突、断连/重连；
  - 基准：连接建立/释放 QPS、工具解析/调用 p95/p99、资源读取吞吐与尾延时。

---

### 具体实现要点（建议）

- 设备会话与客户端池
  - `DeviceMcpSession` 增加 `Close()`：取消 ctx、关闭通道、释放 WS 连接；
  - 客户端池提供 `Range/ForEach` 便于 Shutdown 清理；池持久化统计（连接峰值、累计数）。

- 工具获取与合并
  - 将 `GetToolsByDeviceId` 的合并逻辑下沉到 `ToolRegistry`，并引入 `ToolMergeStrategy`；
  - 返回结构中附带工具来源与版本信息，便于问题定位。

- 资源读取
  - 实现 `GetAudioResourceByTool`：传入 `ctx`、读取分页/流式资源、校验 MIME/长度、限制最大下载大小；错误分类（超时/格式/权限/网络）。

- 错误与日志
  - 统一错误类型：区分用户态错误（4xx）与系统/依赖错误（5xx）；
  - 结构化日志字段：`device_id`、`tool_name`、`source`、`latency_ms`、`attempt`、`err_type`。

---

### 验收标准

- 发布后：
  - 应用优雅关停时，MCP 管理器与设备会话均被清理，无 goroutine 泄漏；
  - 指标展示：活跃设备数、工具合并来源分布、调用成功率/时延直方图；
  - 压测场景下，限流与退避生效、错误率受控、尾延时不恶化超过阈值。
